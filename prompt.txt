- Home
- Services
- Gallery
- Company
- Insights
- Contact
- Start Your Project
- Favorites
- Any other existing page discovered in the project

Review the navbar across every page.

- Make it properly responsive on mobile and tablet.
- Prevent navigation links from overflowing or becoming cramped.
- Implement a polished mobile navigation menu if one does not already exist.
- Ensure menu opening and closing work correctly.
- Make dropdowns usable on touchscreens, not only on hover.
- Make the Start Your Project CTA accessible and appropriately positioned.
- Preserve the existing ATG navbar identity, colors, branding, and desktop appearance.
- Make sure the mobile menu does not cover content incorrectly or create horizontal scrolling.

The navbar must remain consistent across all pages.

### Hero sections

Inspect every page's hero section.

- Correct oversized text on smaller screens.
- Ensure headings wrap naturally.
- Adjust text alignment, spacing, and content widths.
- Resize hero images and backgrounds appropriately.
- Prevent text from overlapping images or important visual elements.
- Keep buttons properly sized and accessible.
- Preserve the visual hierarchy and premium appearance.

### Cards and content sections

Inspect all card layouts, including Services designs, Gallery projects, Insight articles, and other content cards.

- Use responsive grid layouts.
- Adjust the number of columns according to available screen width.
- Ensure cards do not become excessively narrow or oversized.
- Maintain consistent spacing and alignment.
- Make images fill their containers properly without distortion.
- Prevent long titles, descriptions, and prices from breaking layouts.
- Ensure card buttons remain visible and usable.

### Forms and interactive components

Review all forms, search fields, filters, dropdowns, and interactive sections.

- Ensure inputs fit the screen width.
- Make labels and buttons readable.
- Prevent horizontal overflow.
- Make form controls comfortable to use on touchscreens.
- Keep validation messages properly positioned.
- Preserve existing form functionality.

### Images, typography, and spacing

Across the website:

- Use responsive image sizing.
- Preserve image aspect ratios where appropriate.
- Avoid stretched or distorted images.
- Use responsive typography rather than oversized fixed text.
- Adjust section padding and margins at smaller screen sizes.
- Maintain sufficient spacing between elements.
- Ensure text remains readable without excessive zooming.

### Footer

Review the footer on desktop and mobile.

- Improve column stacking on smaller screens.
- Ensure links do not overflow.
- Keep contact information readable.
- Make social media icons appropriately sized.
- Preserve the existing footer design and brand identity.

## Responsive testing sizes

Test the website at approximately these viewport widths:

| Device category | Width |
|---|---:|
| Small mobile | 320px |
| Standard mobile | 375px |
| Large mobile | 430px |
| Tablet | 768px |
| Small laptop | 1024px |

These are testing widths, not rigid breakpoint requirements.

**Important:** Eliminate unintended horizontal scrolling, clipped content, overlapping elements, and unusable controls.

# 3. AUDIT AND COMPLETE THE MATERIAL REVEAL PRELOADER

I previously created four page-transition concepts and selected **Material Reveal (Concept 03)**.

This is the exact preloader design I want used throughout the website.

The existing concept is identified in the transition code as:

`material-reveal`

Inspect the existing transition implementation, especially:

- `assets/js/atg-transitions.js`
- `assets/css/atg-transitions.css`
- The existing transition showcase files
- Any existing shared transition markup
- Every website page's scripts and stylesheets

## Exact visual appearance

Use the existing Material Reveal design. Do not redesign it or substitute another concept.

Preserve its:

- Dark material-inspired surface.
- Subtle sweeping gold sheen.
- Fine crafted texture or pattern.
- ATG wordmark.
- "Architectural Metalwork" subtitle.
- Existing animation sequence and exit motion.
- Existing ATG brand palette.
- Visual proportions and animation character.

The live website must look like the original Material Reveal preview.

## Conduct a complete page-by-page audit

Check every website page and establish whether the transition system has been correctly integrated.

For each eligible page, verify:

- The correct transition stylesheet is loaded.
- The correct JavaScript controller is loaded.
- Required overlay markup is available.
- The selected concept is `material-reveal`.
- Internal navigation activates the transition.
- The destination page completes the reveal properly.
- There are no duplicate overlays or duplicate scripts.

If a page is missing the transition integration, add it.

If a page has an incomplete or incorrectly configured implementation, fix it.

Do not assume every page has the same asset path. Check each page's folder structure and use the correct relative paths.

## Important exception: index page

The existing `index` page has its own initial page-load preloader.

Preserve it exactly as it currently works.

- Do not remove it.
- Do not redesign it.
- Do not replace it with Material Reveal.
- Do not display two preloaders on the initial homepage load.
- Do not interfere with its existing scripts or animations.

Material Reveal should be used for the intended internal page-transition experience across the rest of the site.

Handle navigation involving the homepage carefully so the existing initial preloader and the page-transition system do not conflict.

## Transition reliability

Verify that:

- Internal links trigger the transition correctly.
- External links are not incorrectly intercepted.
- Same-page anchors work normally.
- Downloads and new-tab links retain their behavior.
- Browser back and forward navigation work.
- Rapid clicks cannot create multiple overlays.
- A failsafe prevents the transition from becoming stuck.
- Reduced-motion preferences are respected.

Do not include the transition showcase's preview-only scripts or styles on live pages unless genuinely required. The live website should use the shared transition implementation, not the demo interface.

# 4. IMPLEMENT FUNCTIONAL VIEW DETAILS MODALS ON WEBSITE CARDS

Audit the existing cards throughout the website, especially:

- Services design cards.
- Gallery project cards.
- Other cards that are intended to provide additional information about a particular item.

Where a card is supposed to provide more information, implement a polished and functional **View Details** modal.

Do not add unnecessary View Details buttons to cards that do not need a detailed view.

## Card interaction

Every relevant card should provide a clear View Details action.

When a visitor clicks it:

- Open a modal displaying information about the exact card they selected.
- Do not display identical placeholder information for every card.
- Ensure the correct title, image, description, and other available information are displayed.
- Make the modal visually consistent with the ATG website.

## Services design details

For Services design cards, the modal should display the available information, such as:

- Design name.
- Large design image.
- Category.
- Design description.
- Materials used or proposed materials.
- Finish or customization information where available.
- Price or starting price where available.
- Relevant design features.
- Customization availability.
- Favorite action.
- Start Your Project action.

Clearly distinguish confirmed material specifications from suggested materials.

Do not invent prices, material specifications, or technical details.

If a design has no fixed price, display the existing quote-request wording or an appropriate Request a Quote option instead of inventing a price.

The Start Your Project action should pass the correct design identifier and details into the existing project enquiry flow where supported.

## Gallery project details

For Gallery cards, use a project-focused modal rather than blindly copying the Services modal.

Display available information such as:

- Project name.
- Project image or images.
- Project category.
- Project description.
- Location or project type, only where existing data provides it.
- Other existing project information.

Do not present concept designs as completed projects or invent client names and project details.

## Modal appearance

Create a premium modal that follows the existing ATG visual identity.

The modal should:

- Use a refined dark, cream, and gold treatment.
- Have a clear heading and close control.
- Present images without distortion.
- Use a balanced layout on desktop.
- Adapt into a comfortable full-screen or near-full-screen layout on mobile where appropriate.
- Have readable typography and comfortable spacing.
- Use subtle, smooth entrance and exit animations.
- Avoid excessive decorative effects.

On desktop, a two-column layout with the image on one side and information on the other may be appropriate.

On mobile, stack the image and information vertically and ensure the close control remains accessible.

## Modal functionality

Implement all required interactions:

- Open the modal for the selected card.
- Close using the close button.
- Close when clicking the backdrop, where appropriate.
- Close using the Escape key.
- Prevent background scrolling while open.
- Restore scrolling when closed.
- Ensure the modal does not open multiple times.
- Keep interactions isolated so one modal cannot interfere with another.
- Make controls keyboard accessible.
- Manage focus appropriately when opening and closing the modal.

Use the existing card data and functionality wherever possible.

If the project already has a modal system, improve and reuse it instead of creating a competing implementation.

- Preserve existing IDs, classes, data attributes, and routes unless a change is necessary.
- Keep the code compatible with the current project structure.
- Avoid changing unrelated content or redesigning entire pages unnecessarily.

Do not delete existing functionality just because it is easier to rebuild it.
